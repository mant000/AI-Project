# Milestone：实际成果与意义（2026-11-19）

原始目标是学习搜索状态的价值，辅助LLM发现更好的TSP惩罚规则。当前交付把问题
推进了一步：从“一次惩罚行动的价值”转到“规则连续作用片段的价值”，并把信息覆盖、
模型实际收到的信息、独立路线质量分开测量。英文PDF为四页正文加一页参考文献，
源文件、原始记录、图表、复现入口和历史28模型一并公开；评分版本见仓库根目录
`SUBMISSION.md`。

## 这次新增了什么

在租用的3090/14vCPU服务器上，先用16个原实例的嵌套试点测吞吐，再完成128个
原实例、三条预定轨迹、四个工作阶段的1536状态库。12条预定规则分别做单次惩罚、
25%剩余工作量控制的规则片段、全剩余工作量持续控制。所有分支在相同状态/RNG/
总预算下比较，真实路线计价；持续控制只作条件诊断目标，不提供给生成器。
共56832个唯一分支，试点7104已包含在全量，不重复计数。

剔除标准和正标量倍数两个行为控制后，15360个比较的非零率由0.53%升至10.01%，
与持续控制结果的Spearman由0.063升至0.285。原实例配对非零率增加9.48百分点，
95%区间[7.79,11.26]。这是可重复的机制成果：干预粒度确实影响信息，而不是
把“无非零标签”当作所有状态方法无效。它还不是整程程序收益或学习器成功。

随后固定原始NF4 Qwen7B，A仅真实终点、P另加单次惩罚反馈、F另加规则片段反馈。
四配对发现种子，各32候选/组，共384输出、361有效。失败与重复都计预算；
32发现原实例产生候选，另32选程序，全部12程序冻结后才评价64新开发原实例×五种子。
状态反馈库每个原实例固定取一个状态，全部128个参与统计，两个案例按索引固定选取，
没有挑局部最佳动作。历史中断的91输出未续用。

## 工程修订和计算成本

另有一批完整384次的严格全函数接口试验，112有效。模型常输出裸return，
所以在查看任何新开发成绩前只做了一次统一修订：预填函数头及return前缀，只续写
表达式。旧批完整保留，不按验证收益选批，不合成八个独立发现重复。旧批F−A
为−0.071828，[−0.200663,+0.037376]，也未过门槛。

| 实际工作 | 墙钟 | CPU/GPU口径 |
|---|---:|---|
| 嵌套机制pilot+full | 269秒 | 2480 parent+waited-child CPU秒 |
| strict发现及冻结评价 | 1181秒 | 1976 CPU秒；同步生成1012秒 |
| expression发现及冻结评价 | 1149秒 | 2336 CPU秒；同步生成911秒 |
| 四手写/LKH/LEHD新开发参照 | 540秒 | 10worker质量+串行LEHD，各服务CPU和总childCPU另记 |
| 独立新环境原记录分析 | 14.37秒 | 不加载Torch或模型 |
| 状态重建+完整求解及反馈重放 | 37.40秒 | 160.33 parent+waited-child CPU秒 |

两批共838440输入、26593输出tokens；成本可相加，效用重复不可合并。
Torch峰值allocated8.26GiB，设备采样峰值约9.7GiB；同步生成墙钟不冒充
GPU kernel时间。完整账见`results/milestone-reproduction-v1/cost_ledger.json`。
参照的服务CPU小计不等于完整主进程CPU；环境安装和历史阶段记录另保留，
没有编造每次运行的租金金额。CPU内部并发subprocess的重叠计数从不加成总CPU。

576次独立串行服务时间样本覆盖固定16原实例、seed0、三重复。原生标准GLS
TSP50/100平均约0.039/0.083秒；算术接口标准约0.043/0.085秒。这衡量固定工作量
的实现成本，不是任意秒数的anytime优势，不需要数天串行搜索。
