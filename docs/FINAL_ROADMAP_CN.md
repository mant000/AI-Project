# 从 milestone 到 final：按证据推进的具体路线

目标保持为“利用搜索状态信息帮助发现可部署的 TSP 惩罚规则”。milestone
将一次行动与规则片段的作用粒度分开检验；完整项目仍需解释信息怎样被利用、
在未参与开发的规模/分布上是否有效，以及收益能否抵消获得信息的成本。
以下是交付后的研究路线，不是已完成实验，也不是恢复所有旧待办的指令。
课程 final 截止为 **2026-12-03 23:59 BJT**。

## 11月20–21日：先验证状态信息的可用上限

下一项集中实验是**固定共同候选池的程序筛选**。它消除“A/P/F提示改变后，
候选和父代路径也一起改变”的混杂。冻结原始NF4生成器、单行接口、四个新生成种子，
每种子64输出，共256；重复和失败计入预算，不为凑多样性重试。完整保留输出，
按真实行为去重只节省物理求解，不删去逻辑候选。预定12条手写规则只作单独机制参照，
不混称LLM发现的成果。

使用全新且经历史使用审计的 discovery/bank/selection 原实例，提前写下清单、
规则血缘和观察计划。比较“较短终点评价筛选”与“片段状态筛选加必要终点确认”；
两组看到同一个候选池，按实际CPU秒而非相同调用数设置预算，最后均用完整真实终点
选拔。完整评价保留作离线排序/选择后悔的参照，不能泄漏进筛选输入。
先嵌套16候选×32状态测吞吐，随后最多256候选×256原实例/预定状态，
不按正收益择状态。GPU生成最多1小时；CPU测量最多6小时墙钟（10 workers），
按每批32候选记录实际CPU、失败和排序曲线。给最后独立开发评价留出不同原实例。

继续门槛要在运行前写入新协议：至少8种实际路线行为（不足则说明提议覆盖瓶颈），
在四个共同池中记录所有效应；相同CPU预算的筛选后悔相对下降至少10%，
并在新的独立开发实例上达到至少0.05 gap百分点改善、配对区间上界低于0。
门槛未过，停止扩大状态教师训练；保留筛选成本/信息/效用曲线作为final机制结论。
不能用筛选集上的相关系数代替独立程序质量。

## 11月22–24日：只有 oracle 筛选有用，才学习近似它

若上述门槛通过，训练对象为 **V(s,h,K)**，明确包含状态、规则及控制工作量，
而非把旧的单边价值网络改名。输入可以由当前图、当前规则对边的无未来信息分数、
规范化AST表示及预算构成；正标量规则等价、无标签在线编码、同状态配对均须测试。
先冻结一种小架构、损失和三个模型种子；按原实例及程序亲缘双重划分训练/验证/
预测留出，禁止同父程序的近重复跨越留出。三模型均保留，以预先固定平均集成评价，
不挑收益最好的模型。训练最多20轮/种子、总GPU上限4小时；每轮记录排序后悔、
非零覆盖、假偏好、推理成本。验证只负责既定早停，独立开发评价只在冻结后进行。

只有学习器在全留出实例和程序上保留oracle筛选收益、且总标签+训练+推理成本
不超过预先固定预算，才进入正式候选筛选流程。否则保留直接测量参照，
不把训练loss下降或参数更新写成发现收益。已有共同SFT作为独立程序先验参照；
不默认继续GRPO。新GRPO必须另外解释它解决哪个已识别瓶颈，并先冻结奖励和预算，
没有这些依据就不投入第二轮适配。

## 11月25–27日：冻结 final 方法与评价，预留质量检查

保留原始生成器/共同SFT的终点反馈参照、标准GLS、预定手写规则和LKH/LEHD强参照。
新筛选/学习方法只有通过上述门槛才加入。每个独立发现种子先在program_select
上选程序，冻结所有种子而非挑一个最好程序；提交源码、hash、别名映射、模型集成、
工作量/墙钟预算及异常处理。不同血缘但行为相同的程序可物理复用评价，全部逻辑重复
仍保留。冻结文件有UTC时间、Git SHA和输入身份，随后禁止依据final改方案。

用非final的不同规模几何实例和已开发实例做吞吐与距离约定fixture，检查连续欧氏
与TSPLIB EUC_2D整数计价、参考路线解析和超时保存。旧R5-v2调度草案未经验证，
须先过测试，不能用v1的测试替代。按试点预测完整质量评价：优先保留1194原实例
（Joshi test 768、INViT OOD384、TSPLIB42）×五求解种子。最终规模与预算在开final
前确定；若预测超预算，提前说明如何采用分层预定子集，不能看质量后缩减。

## 11月28–30日：一次独立 final，并单列服务时间

质量使用共同精确工作量，强参照使用各自明确预算，所有返回路线重新计价，
负gap保留。各规模/分布分别报告原实例统计，五求解种子先实例内平均；所有发现重复
分别展示，再计算配对区间。原始测量/源码/hash/失败与所有成本保留。

计时采用预先指定、覆盖规模/分布的代表子集，逐个方法串行跑、重复三次并记录冷启动。
先测小批吞吐，再冻结可在**4小时墙钟以内**完成的样本量；不执行旧的约100小时
“所有规则持续串行搜索”草案。共同工作量服务时间与anytime质量曲线是两个问题，
需要后者时另固定少量时间点和子集，不能把并发worker用时当单任务墙钟优势。

质量评价服务器总预算暂留12小时、时间样本4小时，GPU强参照不与生成/训练争用。
每完成一个规模/分布就核对完成数、重复身份、CPU/GPU成本、磁盘余量和超时比例；
失败超过1%先查实现与资源，不扩大实验或静默删失败。所有停止原因写入记录。
保留月租现有3090，不以更多GPU作为默认前提；至少留8GB磁盘，关闭阶段移至已有备份盘。
